# MRIO Scripts and Concordances

This directory contains the reproducible workflow used to generate the PostGrowth input workbooks and the intermediate diagnostic artifacts needed to audit that workflow.

## Structure

| Path | Role |
| --- | --- |
| `aggregate_iot_by_mapping.py` | Re-aggregate already split IO tables using a mapping CSV and optionally write Eurostat-shaped SFC workbooks. |
| `build_energy_balances_65sectors_primary_sources.py` | Build the direct-mapped 65-sector Austrian energy-balance workbook on the model carrier basis. |
| `generate_mapping_csvs.py` | Regenerate the annotated EXIO-to-Eurostat and energy-sector mapping CSVs from the checked-in rules plus Eurostat output shares. |
| `split_eurostat_energy_by_exiobase.py` | Split Eurostat IO energy sectors using EXIO profiles, run local/global balancing, and emit diagnostics. |
| `pipelines/split_energy_balances_65NACE2sectors_aggregate_energy_sources.sh` | End-to-end shell entrypoint for the direct-mapped energy-balance workbook export. |
| `pipelines/at_2021_energy_green_brown.sh` | End-to-end shell entrypoint for split-and-reaggregate Eurostat IO workbooks; despite the filename it accepts `EUROSTAT_TIME` and works for 2020 and 2021. |
| `pipelines/export_postgrowth_inputs.sh` | One-command wrapper that exports the current PostGrowth input set into the sibling PostGrowth repo. |
| `diagnostics/` | Targeted one-off diagnostics used to inspect mapping details, CO2 mappings, and outliers. |

## Mapping Files

The workflow depends on the following checked-in concordance files under `scripts/mappings/`.

| File | Generated by | Role in workflow |
| --- | --- | --- |
| `exio_to_eurostat_cpa.csv` | `generate_mapping_csvs.py` | Weighted EXIOBASE product to Eurostat CPA_65 concordance used for mapping diagnostics and Eurostat-sector CO2/intensity outputs. |
| `exio_energy_split_cpa_with_electricity_source.csv` | checked in | Split map from the two aggregate Eurostat energy sectors to detailed EXIO energy subsectors, preserving electricity-by-source detail. |
| `exio_energy_split_cpa_no_electricity_source.csv` | checked in | Alternate split map without electricity-by-source detail. |
| `energy_green_brown_2sector_from_split_subsectors.csv` | checked in | Collapse the detailed split subsectors into the analytical `ENERGY_GREEN` / `ENERGY_BROWN` sectors. |
| `energy_balance_to_nace2_mapping.csv` | checked in | Direct-combustion bridge from raw Eurostat energy-balance rows to the 65 IO sectors plus households, including explicit refinery and electricity/heat transformation rows where applicable. |
| `siec_to_primary_energy_sources.csv` | checked in | Map Eurostat SIEC carriers into the model’s primary-source carrier basis. |
| `energy_primary_source_buckets.csv` | checked in | Group the primary-source carriers into the analytical brown/green buckets used in the exported workbook. |

The canonical mapping CSV schema is mandatory for runtime use. Legacy lightweight mapping files are not supported, and all checked-in mapping files must carry the full header including `source_balance_role`, `target_sector_role`, and `include_in_direct_energy`.

## Reproducible Commands

All commands below assume the repo root is `/home/agilra/EcolEconModels/MRIO` and use the local virtual environment interpreter `.venv/bin/python`.

### 1. Regenerate mapping CSVs

```bash
cd /home/agilra/EcolEconModels/MRIO
.venv/bin/python scripts/generate_mapping_csvs.py \
  --geo AT \
  --year 2021 \
  --eurostat-storage-folder data/eurostat \
  --outdir scripts/mappings
```

### 2. Export the direct-mapped energy-balance workbook

```bash
cd /home/agilra/EcolEconModels/MRIO
OUT_XLSX=/home/agilra/EcolEconModels/PostGrowth-SFC-Austria/Energy_Balances_2021_Eurostat_green_brown.xlsx \
POSTGROWTH_SHEET_NAME=Energy_1.0 \
SPLIT_ENERGY_GREEN_BROWN=1 \
bash scripts/pipelines/split_energy_balances_65NACE2sectors_aggregate_energy_sources.sh
```

### 3. Export split-and-reaggregated IO workbooks

```bash
cd /home/agilra/EcolEconModels/MRIO
EUROSTAT_TIME=2020 \
TEMPLATE_XLSX=/home/agilra/EcolEconModels/PostGrowth-SFC-Austria/IOT_Austria_2021_Eurostat.xlsx \
SFC_OUTNAME=IOT_AT_2020_{variant}_energy_green_brown.xlsx \
bash scripts/pipelines/at_2021_energy_green_brown.sh
```

```bash
cd /home/agilra/EcolEconModels/MRIO
EUROSTAT_TIME=2021 \
TEMPLATE_XLSX=/home/agilra/EcolEconModels/PostGrowth-SFC-Austria/IOT_Austria_2021_Eurostat.xlsx \
SFC_OUTNAME=IOT_AT_2021_{variant}_energy_green_brown.xlsx \
bash scripts/pipelines/at_2021_energy_green_brown.sh
```

### 4. Export the full PostGrowth input set

```bash
cd /home/agilra/EcolEconModels/MRIO
bash scripts/pipelines/export_postgrowth_inputs.sh
```

By default this writes:

- `../PostGrowth-SFC-Austria/Energy_Balances_2021_Eurostat_green_brown.xlsx`
- `../PostGrowth-SFC-Austria/IOT_AT_2020_TOTAL_energy_green_brown.xlsx`
- `../PostGrowth-SFC-Austria/IOT_AT_2021_TOTAL_energy_green_brown.xlsx`

## Diagnostic Outputs

`split_eurostat_energy_by_exiobase.py` now writes the following audit files alongside each flow output:

| File | Meaning |
| --- | --- |
| `balance_info.json` | Balancing method and convergence diagnostics for the split table. |
| `energy_split_report.xlsx` | Human-readable workbook summarizing the split profiles and balancing outputs. |
| `mapped_output_consistency.csv` | Written for `TOTAL` flows when the EXIO-to-Eurostat output sanity check is evaluated. Contains the Eurostat output reference, mapped EXIO producer output, scalar normalization factor, and scaled differences by CPA sector. |
| `eurostat_sector_co2_intensity.csv` | EXIO direct-emissions intensities reaggregated to Eurostat sectors using `exio_to_eurostat_cpa.csv`. |

`mapped_output_consistency.csv` is diagnostic, not an additional balancing target. The hard gate checks total-scale consistency between mapped EXIO producer output and the Eurostat product-use reference; the per-sector comparison is preserved as an audit artifact because the EXIO-to-CPA bridge is approximate by construction.

## Notes on Reproducibility

- `generate_mapping_csvs.py` should be run for the same `geo` and `year` as the Eurostat IO table used downstream, because ambiguous one-to-many mappings are resolved with Eurostat output shares for that exact table.
- The IO split step uses EXIOBASE producer-side output for mapping diagnostics and emissions intensity denominators, but destination-side use slices for the actual split profiles. Those are distinct objects and should not be conflated.
- The PostGrowth model consumes the exported workbooks directly; it no longer redoes the brown/green split inside R.
