# MRIO Scripts and Concordances

This directory contains the reproducible workflow used to generate the PostGrowth input workbooks and the intermediate diagnostic artifacts needed to audit that workflow.

## Structure

| Path | Role |
| --- | --- |
| `aggregate_iot_by_mapping.py` | Re-aggregate already split IO tables using a mapping CSV and optionally write Eurostat-shaped SFC workbooks. |
| `build_energy_balances_65sectors_primary_sources.py` | Build the direct-mapped 65-sector Austrian energy-balance workbook on the model carrier basis. |
| `generate_mapping_csvs.py` | Legacy utility for rebuilding mapping CSVs from Eurostat output shares; the pipelines now use the checked-in static CSVs. |
| `split_eurostat_energy_by_exiobase.py` | Split Eurostat IO energy sectors using EXIO profiles, run local/global balancing, and emit diagnostics. |
| `pipelines/split_energy_balances_65CPAproducts_aggregate_energy_sources.sh` | Legacy-named end-to-end shell entrypoint for the direct-mapped energy-balance workbook export to the repo's 65-product CPA-based IO targets. |
| `pipelines/at_2021_energy_green_brown.sh` | End-to-end shell entrypoint for split-and-reaggregate Eurostat IO workbooks; despite the filename it accepts `EUROSTAT_TIME` and works for 2020 and 2021. |
| `pipelines/at_2021_fuels.sh` | Canonical 2021 fuels entrypoint: split the selected Eurostat CPA sectors with local balancing, generate the identity pass at runtime, then export both disaggregated and reaggregated TOTAL / DOM / IMP workbooks. |
| `pipelines/run_exio_eurostat_concordance_audit_all_flows.sh` | Shell entrypoint for the domestic/imports/total EXIOBASE-Eurostat concordance audit and the consolidated summary outputs. |
| `pipelines/export_postgrowth_inputs.sh` | One-command wrapper that exports the current PostGrowth input set into the sibling PostGrowth repo. |
| `diagnostics/` | Targeted one-off diagnostics used to inspect mapping details, CO2 mappings, and outliers. |

### Direct official CPA64/CPA65 maps

Run `scripts/mappings/build_exiobase3_to_cpa_from_official_direct.py` to convert
`data/exiobase_concordance_sources/cpasut64_exiobase3p.csv` into:

```text
scripts/mappings/generated/official_direct/exio_to_eurostat_cpa64_products_from_official_direct.csv
scripts/mappings/generated/official_direct/exio_to_eurostat_cpa65_products_from_official_direct.csv
```

The source file is a binary CPA64-to-EXIOBASE3 incidence relation. The generated
files use the canonical EXIOBASE3-to-CPA runtime orientation and remain the
unchanged provenance baseline. Fuels and fuels_more default instead to the
checked-in reviewed derivative
`scripts/mappings/exio_to_eurostat_cpa65_products_official_direct_reviewed.csv`,
which narrows only `p23.3` Nuclear fuel, the `p24.*` chemicals/pharmaceuticals
family, and `p33` Medical, precision and optical instruments, watches and clocks.
The reviewed choices live entirely in mapping data; no Python special case applies
them. Retained many-to-many rows still use the existing output/use-share resolver,
and the concordance-aware closure generator resolves the sparse analytical
reaggregation recipes before strict child-coverage validation. The green/brown
wrapper retains its older C20-only concordance because its separate analytical
mapping is intentionally unchanged.

The workflow depends on the following checked-in concordance files under `scripts/mappings/` plus the user-editable split and reaggregation helper tables under `scripts/pipelines/`.

| File | Generated by | Role in workflow |
| --- | --- | --- |
| `exio_to_eurostat_cpa.csv` | checked in | Weighted EXIOBASE product to the repo's 65-product CPA-based IO targets, used for mapping diagnostics and Eurostat-sector CO2/intensity outputs. |
| `exio_energy_split_cpa_with_electricity_source.csv` | checked in | Split map from the two aggregate Eurostat energy sectors to detailed EXIO energy subsectors, preserving electricity-by-source detail. |
| `exio_energy_split_cpa_no_electricity_source.csv` | checked in | Alternate split map without electricity-by-source detail. |
| `pipelines/fuels_split.csv` | user-editable | Split manifest for the canonical fuels workflow. |
| `pipelines/fuels_more_split.csv` | user-editable | Expanded split manifest for the fuels-more workflow. |
| `pipelines/energy_green_brown_split.csv` | user-editable | Split manifest for the analytical green/brown energy view. |
| `pipelines/fuels_reaggregation.csv` | user-editable | Reaggregation table for the canonical fuels workflow. |
| `pipelines/fuels_more_reaggregation.csv` | user-editable | Expanded reaggregation table for the fuels-more workflow. |
| `pipelines/energy_green_brown_reaggregation.csv` | user-editable | Reaggregation table for the analytical green/brown energy view. |
| `energy_balance_to_cpa65_products_mapping.csv` | checked in | Legacy filename retained for compatibility; direct-combustion bridge from raw Eurostat energy-balance rows, many of which are defined on the activity side in NACE terms, to the repo's 65-product CPA-based IO targets plus households, including explicit refinery and electricity/heat transformation rows where applicable. |
| `siec_to_primary_energy_sources.csv` | checked in | Map Eurostat SIEC carriers into the model’s primary-source carrier basis. |
| `energy_primary_source_buckets.csv` | checked in | Group the primary-source carriers into the analytical brown/green buckets used in the exported workbook. |

The canonical mapping CSV schema is mandatory for runtime use. Legacy lightweight mapping files are not supported. Static concordances stay under `scripts/mappings/`; split and reaggregation helper tables are sourced only from `scripts/pipelines/` and should not be duplicated elsewhere. For split and reaggregation tables, `source_code` is the runtime key; labels are descriptive metadata only.

Terminology note: Eurostat's NACE classification is for economic activities, while CPA is for products by activity. The energy-balance bridge in this repo therefore uses NACE only on the source-definition side of some correspondence logic; its operative targets are the repo's 65-product CPA-based IO rows plus households. The retained `nace2` naming in one bridge filename and one shell script path is historical compatibility naming rather than the operative target classification.

## Diagnostic Outputs

`split_eurostat_energy_by_exiobase.py` now writes the following audit files alongside each flow output:

| File | Meaning |
| --- | --- |
| `split_info.json` | Donor-block reconstruction method, fallback count, resolved donor scope, and exact SHA-256 provenance for the EXIO source ZIP plus any region/split/concordance mapping CSVs used. The configured DOI is retained as a locator, not substituted for the byte hash. No RAS/GRAS balancing is applied. |
| `energy_split_report.xlsx` | Human-readable workbook summarizing the split profiles and reconstruction diagnostics. |
| `mapped_output_consistency.csv` | Written for `DOM`, `IMP`, and `TOTAL` flows when the EXIO-to-Eurostat output sanity check is evaluated. Contains the Eurostat `Z + non-export final demand` output reference, mapped EXIO flow output, scalar normalization factor, and scaled differences by CPA sector. |
| `mapped_output_flow_identity.csv` | Hard internal accounting check that `DOM + IMP` matches `TOTAL` for Eurostat and mapped-EXIO destination-use totals, using strict flow-identity tolerances independent of cross-dataset mapping-consistency diagnostics. |
| `exio_environmental_extensions.csv` | Raw EXIO production `F` and direct-final-demand `F_Y` evidence with source units and denominators. `F_Y` stays on its final-demand-category axis. |
| `environmental_extensions.csv` | Boundary-aware target-sector direct environmental estimates. DOM uses scope-production coefficients, IMP uses origin-retaining import coefficients, and TOTAL is derived from the target DOM+IMP components. |

`mapped_output_consistency.csv` is diagnostic by default, not an additional balancing target. Cross-dataset level gaps between mapped EXIO destination-use totals and Eurostat non-export product-use totals are written for inspection because the EXIO-to-CPA bridge is approximate by construction. The hard gate is the internal flow identity in `mapped_output_flow_identity.csv`: `DOM + IMP = TOTAL`, checked with strict flow-identity tolerances. Use `--strict-mapping-consistency-check` only when you intentionally want EXIO-vs-Eurostat level gaps to fail the run.

### 5. Export canonical fuels IO workbooks

No workbook input is needed to generate the mapping files for the fuels workflows. The identity pass is synthesized from the split-stage artifacts at runtime. The official Eurostat workbook is required only as the authoritative order, label, formatting, and layout schema for each exported workbook; its numbers are never allocation targets.

```bash
cd /home/agilra/EcolEconModels/MRIO
TEMPLATE_XLSX=/home/agilra/EcolEconModels/PostGrowth-SFC-Austria/IOT_Austria_2021_Eurostat.xlsx \
bash scripts/pipelines/at_2021_fuels.sh
```

For a non-AT target, enabling `WRITE_SFC_WORKBOOK=1` requires an explicit `TEMPLATE_XLSX`; the Austrian default template is never reused for another geography.

This writes three families under `outputs/`:

- split flow tables plus disaggregated TOTAL / DOM / IMP workbooks with `_fuels_split` in the filename
- reaggregated TOTAL / DOM / IMP workbooks with `_fuels_reaggregated` in the filename
- a temporary identity CSV that is generated from the split-stage `exio_selected_sectors.json` files and deleted automatically when the wrapper exits

The fuels pipeline no longer needs a workbook to author mapping CSVs. The split pass is driven by the committed split CSV, and the identity mapping is synthesized from split-stage artifacts at runtime so the workbook export stays reproducible without checking in an extra identity CSV.

The canonical IO accounting pass derives domestic output from domestic transaction row use and imports from imported transaction row use. It constructs `TOTAL = DOM + IMP` for `Z` and the atomic final-demand basis, regenerates displayed final-demand controls, closes the production account through `B2A3N`, and rebuilds the applicable `V`/`M` controls. `A_DOM` is the cleared domestic Leontief matrix; `A_IMP` and `A_TOTAL` are imported and total input requirements per unit of the same domestic output, not standalone Leontief systems. The fuels donor-block path does not invoke RAS/GRAS.

Parent products follow the official template order, while split children follow committed mapping-file row order within each parent. Numeric primitive template cells require matching SDMX observations; blanks and `:` remain missing/non-applicable rather than becoming zero. Canonical split and reaggregated triplets pass the generated full-table accounting validator before export.

## Notes on Reproducibility

- The checked-in helper CSVs under `scripts/pipelines/` are the source of truth for split and reaggregation pipeline runs. If you manually tweak them, rerun the affected pipelines directly rather than regenerating them as part of the workflow.
- The IO split step uses destination-side use slices for split profiles and mapped-output diagnostics. Boundary-aware environmental sidecars use scope-production coefficients for DOM and origin-retaining direct import coefficients for IMP; TOTAL is derived from the target DOM+IMP components. The optional quantity/value proxy remains a separate singleton-scope feature and is disabled for grouped donor scopes.
- The PostGrowth model consumes the exported workbooks directly; it no longer redoes the brown/green split inside R.

### Eurostat Energy Balance dictionary

The Energy Balance pxp split pipeline must validate all `nrg_bal` and `siec` selectors against an official metadata-derived dictionary:

```bash
.venv/bin/python scripts/build_eurostat_energy_balance_dictionary.py \
  --geo AT \
  --year 2021 \
  --out scripts/mappings/eurostat_energy_balances_dictionary.csv
```

The generated file has schema:

```text
dataset,dimension,code,label,description,provenance_source
```

Do not hand-type Energy Balance code labels in active mapping files. Use official Eurostat SDMX metadata via this generated dictionary.

### Run the Eurostat Energy Balances pxp split path

This wrapper uses the official Energy Balance dictionary and the committed split,
reaggregation, technology, and price recipes under
`scripts/pipelines/eurostat_energybalances_split/`. It does not generate selector
quantities in shell; quantity lookup is handled by the Python split-plan module.

```bash
bash scripts/pipelines/at_2021_energy_balance_pxp.sh
```

Default outputs are written under `outputs/AT_2021_energy_balance_pxp/`, with
plan-level diagnostics in `plan_diagnostics/` and per-flow matrices in
`stk_flow=DOM/`, `stk_flow=IMP/`, and `stk_flow=TOTAL/`.


### Validate Energy Balance pxp outputs

After running `scripts/pipelines/at_2021_energy_balance_pxp.sh`, validate the output directory with:

```bash
.venv/bin/python scripts/validate_energy_balance_pxp_outputs.py   --outdir outputs/AT_2021_energy_balance_pxp   --flows DOM,IMP,TOTAL   --require-reaggregated   --write-summary outputs/AT_2021_energy_balance_pxp/validation_summary.csv
```

The validator checks plan diagnostics, split/reaggregated matrix label consistency, `x = Z 1 + Y 1`, `A = Z / x`, absence of duplicated plan diagnostics in flow folders, and absence of `EB_*` children after reaggregation.

### Final Eurostat Energy Balance pxp split/reaggregation run

The canonical final run for the Energy-Balance-based Eurostat pxp split/reaggregation is:

```bash
bash scripts/pipelines/run_at_2021_energy_balance_pxp_outputs.sh
```

By default this uses cached Eurostat data under `data/eurostat`, the committed EB mapping recipe under
`scripts/pipelines/eurostat_energybalances_split/`, the official metadata-derived dictionary at

### Region-aware fuels/fuels-more production path

WP4 wires the existing fuels/fuels-more sector mappings to the generic geography and
environmental APIs. AT is a singleton donor scope and uses no region mapping CSV.
`EU27_2020` is compiled from `scripts/pipelines/region_scopes/eu27_2020.csv` against
the actual EXIO source-region basis; RoW is its complement. The target monetary EU
IOT is the directly published Eurostat `geo=EU27_2020` table, not a sum of national
Eurostat IOTs. DOM, IMP/RoW and TOTAL environmental sidecars keep distinct boundaries
and are reaggregated by summing physical numerators and their matching monetary
denominators before deriving intensity. Aggregate exports exclude intra-scope trade.
